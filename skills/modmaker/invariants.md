# Invariants — the eight rules every stage obeys

Read this once at pipeline start and keep it in context. Unlike a stage page, it is **not**
lazily loaded: these rules constrain what may be claimed or generated at *every* stage, so
there is no single stage at which to read them.

Each rule is stated once, here. A stage page names it (`INV-3`) and adds only what is
specific to that stage — a concrete API family, an exact marker, one command. A stage page
that restates the general rule in its own words creates a second copy, and the two drift
until the weaker wording is the one someone follows.

What the eight have in common: each is a way the delivered Mod ends up **false while every
local stage looks like it passed**. That is the failure this pack exists to prevent, and it
is why these are invariants rather than advice.

## INV-1 — Report the tier reached, never the tier wanted

A green build is not a load; a load is not an effect. Report exactly which tier was reached
and name a missing one as missing.

- A harness that could not reach its scenario is **tier-1**, not a tier-2 failure of the Mod.
- A hand-driven dev-console observation is **manually observed**, not an automated tier-2 pass.
- A skipped, waived, or human-reserved check is an **exception**, never a pass.
- A trigger log, a model-only state, a resource path, or a successful `.pck` is not a proof.

Fires at: build, verify, repair, finalize.

## INV-2 — Observed reality outranks the artifact

Diagnose from the real log, the real compiler signature, and the real host — never from an
exit code or from memory of what was written. When code and observed reality disagree,
reality is right and the code is the thing to change.

A code change reaches the running game only through a rebuild, so re-running against a stale
build proves nothing about the fix.

Fires at: build, verify, repair.

## INV-3 — An ungrounded route is a pack gap, not a guess

Every generated symbol comes from this pack: a recipe, a reference, a catalog, or `errors.md`.
When the needed route is not there, say exactly what is missing and stop. Do not try a second
guess, and do not widen the request to something the pack does happen to carry.

A public framework Package this pack has not yet written a SPEC block or recipe for is
**missing authoring work**, not an unsupported API. Say which of the two it is.

Fires at: spec, scaffold, author, repair.

## INV-4 — Never manufacture evidence for a claim only observation can settle

Static reasoning, a clean compile, and a plausible formula do not make a value balanced, fun,
tuned, or playtested. A missing measurement, trigger rate, formula input, or human play result
stays an **open hypothesis** with that word attached.

A user-reported observation is evidence from the user. Recording one does not make it measured,
reproduced, or diagnosed.

Fires at: route, interview, design, spec, verify.

## INV-5 — Stop at a visible difference; never substitute quietly

When the supported route produces something a player would notice is different from what was
asked — a composed description instead of a replaced one, a fallback icon instead of custom
art, one target instead of many — stop and say so in those terms. Continue only after the user
accepts that exact difference, even when every value is already settled and even when they
asked not to be asked again.

Half-doing the request and reporting it as done is the specific failure here. An accepted
difference is a decision; an unremarked one is a defect.

Fires at: route, interview, design, spec, author.

## INV-6 — Preserve what the user already settled

Settled decisions, rejected alternatives, identifiers, content, completed stages, and unrelated
artifacts survive every later turn. A revision touches its delta and nothing else; a resume
continues from the artifacts rather than re-deriving them from the conversation.

Re-asking a settled question is not a safe default. It discards a decision the user already
made and invites a different answer.

Fires at: state check, route, interview, design, spec.

## INV-7 — Stay inside the pinned RitsuLib boundary

The pinned RitsuLib compat profile is the only path. Never restore BaseLib, an Alchyr template,
or a historical workaround; never emit prompt-derived Harmony, reflection, Publicizer, or IL.
A capability bridge that a past version offered is not a current editing recipe.

This holds under repair pressure too: a failing build is not a reason to reach outside the
boundary for something that compiles.

Fires at: scaffold, author, build, repair.

## INV-8 — Never edit the installed pack from inside a run

The installed skill is regenerated by `publish.sh` from source under `games/sts2/`. A run
consumes it read-only. New quirks, error signatures, and fixes go into the **project's**
`MEMORY.md`, flagged for the maintainer to promote into source.

An in-place edit makes the next run unreproducible and silently deletes itself at the next
publish.

Fires at: every stage, and especially repair.
